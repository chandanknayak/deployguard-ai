How DeployGuard AI Works & Step-by-Step Demo Playbook

Clear explanation of every component so you can operate & present the entire platform confidently.

Step 1 · Setup Repo

Create Sandbox GitHub Repo

Link your GitHub PAT (encrypted with SHA-256 CTR + HMAC-SHA256 in MongoDB) and click Create & Seed Real GitHub Repo in Tab 1. It creates a real repo with services/payments.py + routes/checkout.py + unit tests.

Step 2 · RBAC Team

Invite & Assign Roles

Create teammates in Setup & Team (Developer, Reviewer, DevOps Admin) and optionally invite GitHub handles as repo collaborators. Every sensitive backend endpoint enforces JWT role checks.

Step 3 · Developer PR

Open Real PR & Scan AST

Click + Open Test PR on GitHub (Safe, Warn, or Breaking). DeployGuard parses the diff, runs Python ast Base-vs-Head diff + cross-file import graph, and writes real Commit Status + PR Comment on GitHub.

Step 4 · Reviewer Sign-Off

Official PR Review & Safe Merge

Switch to a Reviewer account: submit APPROVE / REQUEST_CHANGES to GitHub. Reviewer can merge PASS PRs, while BLOCK PRs stay locked for DevOps Admin.

Step 5 · DevOps Admin

Override, Merge & Deploy Probe

Switch to DevOps Admin: authorize an audited Admin Override on blocked PRs (requires justification), merge on GitHub, and trigger Canary/Staging deployment with real SSRF-safe HTTP health probe.

Scoring Formula

Weighted 40 / 30 / 20 / 10 Gate

AST Structural Diff (40%) + Cross-File & Graph Blast (30%) + Critical Path (20%) + Test Gap (10%). Pure docs/assets always score 0/100 PASS. Broken API routes enforce >=74 BLOCK.
